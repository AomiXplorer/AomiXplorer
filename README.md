## About

I like the part before the code: opening a product, clicking through it, and working out why it
was built the way it was. Most of what I publish started there, then turned into an API, an app,
or a rewrite.

TypeScript and Next.js most days, Kotlin when it should be an app, Python when the job is a tool
that has to run anywhere and cannot ask for anything first.

Currently building [aomi](https://github.com/AomiXplorer/aomi), a skill for AI agents that keeps
engineering and design in one loop, and maintaining [Cyronime](https://cyronime.my.id), a public
API that began as a shortcut for my own apps.

Two different things, worth keeping apart:

- [The real contribution graph](https://github.com/AomiXplorer) is GitHub's own record of commits, issues and reviews. It turns green when work happens and stays pale when it does not, and nothing in a README can change that.
- The snake is a drawing, not a record. A workflow in this repository rebuilds it every night from that same public data, using GitHub's own greens. It creates no commits and proves no activity: a quiet day simply leaves the snake with nothing to eat.
